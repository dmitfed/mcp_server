# Запуск сервера и контракт MCP

[План](../plan.md) · [Модуль v1](module-v1.md) · [Приёмка](../quickstart.md)

## Локальный запуск

`mcp-core --config PATH [--port PORT]` загружает конфигурацию и запускает
Streamable HTTP на `http://127.0.0.1:PORT/mcp`. Порт по умолчанию — `8765`.
Клиент запускает процесс с `--port 0`, чтобы ОС выделила свободный порт.
`mcp-core --version` выводит версию и завершает процесс.

После проверки конфигурации сервер резервирует loopback-сокет и передаёт его
Uvicorn. В stdout он выводит одну JSON-строку с фактическим адресом, например
`{"mcp_url":"http://127.0.0.1:49152/mcp"}`. Запись сообщает адрес, а успешный
MCP discovery подтверждает готовность endpoint. Сбой привязки порта завершает
процесс с ненулевым кодом и диагностикой.

```toml
config_version = 1
disabled_tools = []
grants = []

[[modules]]
manifest = "demo-module.json"

[execution]
timeout_seconds = 10
max_concurrent_calls = 4
```

Для пустого профиля достаточно `config_version = 1` и `modules = []`.
Отключённые имена относятся к зарегистрированным инструментам. Пути разрешаются
относительно конфигурации, если они заданы относительными. Полномочия происходят
из параметра `grants` в доверенном файле оператора. Конфигурация и манифесты
читаются при запуске. Отсутствующий файл, неизвестная версия, нарушенная схема
или дубликат завершают запуск с ненулевым кодом и безопасной диагностикой.

## HTTP и доступ

- MCP обслуживается через SDK `streamable_http_app` с `stateless_http=True`
  и `json_response=True` на едином endpoint `/mcp`. Клиент подтверждает редакцию
  `2026-07-28` и capability `tools` через discovery.
- Сокет привязан к `127.0.0.1`. Допустимый HTTP `Host` — `127.0.0.1:<порт>`
  с фактическим портом. При порте 80 также допустим `127.0.0.1` без номера порта.
  Отсутствующий или неверный `Host` отклоняется до обработки MCP. Приложение
  возвращает HTTP 421, если запрос дошёл до него. HTTP-сервер может вернуть
  HTTP 400 за отсутствующий или синтаксически неверный заголовок раньше.
- Для запроса с допустимым `Host` разрешено отсутствие `Origin`. Наличие
  `Origin`, включая пустое значение, даёт HTTP 403 до обработки MCP.
  Проверка наличия заголовка дополняет валидацию SDK, которая принимает
  пустое значение. Uvicorn работает с отключёнными proxy headers и access log.
- Все допущенные локальные клиенты экземпляра получают полномочия из его
  доверенной конфигурации. В проверочном профиле `grants = []`. Модуль применяет
  полномочия к защищённым операциям.

## Операции MCP

- `tools/list` возвращает доступные инструменты с `name`, `description` и
  `inputSchema`. Пустой реестр возвращает `tools: []`. Порядок стабилен по имени.
- `tools/call` принимает имя и JSON-объект аргументов и по успешному завершению
  возвращает объект в `structuredContent` и его JSON-представление в `content`.
- Неверная структура параметров и неизвестный или отключённый инструмент дают
  ошибку JSON-RPC. Ядро применяет проверку входной схемы к существующему
  доступному инструменту до запуска обработчика.
- Невалидный вход инструмента, отказ модуля в защищённом доступе, ошибка или
  некорректный выход обработчика, истечение лимита и перегрузка дают
  `isError: true` и безопасное текстовое сообщение. Коды проекта
  `invalid_arguments`, `permission_denied`, `handler_error`, `tool_timeout`,
  `busy` и `rate_limited` идентифицируют исход в журнале.

## Граница исполнения и журналов

На один вызов запускается один процесс с отдельными каналами. Рабочий процесс
получает JSON-запрос с проверенными аргументами и доверенным контекстом и возвращает
один JSON-объект результата или фиксированный исход ошибки. До импорта обработчика
исполнитель резервирует дескриптор канала ответа и перенаправляет обычный stdout
и stderr в `/dev/null`. Сообщения родителя к дочернему процессу и ответы ограничены
1 МиБ на направление.

Отсчёт `timeout_seconds` по монотонным часам начинается при допуске вызова,
в момент резервирования слота. Лимит включает запуск исполнителя и получение
и проверку результата. Истечение срока до готовности результата даёт
`tool_timeout`. Сервер возвращает ошибку до ожидания выхода исполнителя.
Уборка выполняет завершение, принудительную остановку при необходимости
и сбор процесса. Слот освобождается после сбора.

Отсутствие свободного слота даёт `busy`. Исчерпание лимита частоты даёт
`rate_limited`. В обоих случаях исполнитель для отклонённого вызова
не запускается. Ограничение частоты — 10 допущенных вызовов в секунду,
начальный запас — 4 вызова. Лимиты применяются на процесс MCP-сервера.

В режиме сервера stdout содержит только запись адреса. Диагностические записи
о вызове в stderr содержат время, зарегистрированное имя при наличии,
длительность, статус и фиксированный код. Логи SDK и Uvicorn фильтруются до
записи, включая ошибки HTTP-заголовков. Диагностика запуска указывает
недостающий файл, конфликтующее имя или поле конфигурации без содержимого файла.
