# Модель данных — офлайн-ядро MCP-сервера

[Спецификация](spec.md) · [Контракт модуля](contracts/module-v1.md) ·
[Контракт MCP](contracts/server-mcp.md)

| Сущность | Поля | Связь и область жизни |
|---|---|---|
| Конфигурация сервера | Одна версия конфигурации, пути к манифестам, выбранные имена отключённых инструментов, разрешения, лимиты | Загружается при запуске. Один экземпляр конфигурации создаёт один реестр. |
| Экземпляр сервера | Дочерний процесс, порт loopback, адрес `/mcp`, состояние запуска | Хост владеет процессом от запуска до завершения. Запись адреса сообщает выделенный порт. Готовность подтверждается MCP discovery. |
| Модуль | `module_id`, версия контракта, список объявлений инструментов | Явно подключается одним путём манифеста. Идентификатор уникален в конфигурации. |
| Объявление инструмента | `name`, `description`, `input_schema`, адрес обработчика | Принадлежит одному модулю. Имя глобально уникально среди заявленных инструментов. |
| Контекст вызова | Доверенные разрешения, настроенные оператором | Ядро строит его отдельно от JSON-аргументов. Модуль применяет полномочия перед защищённой операцией. |
| Вызов | Имя, JSON-объект аргументов, монотонный дедлайн, ссылка на дочерний процесс, итог | Существует в памяти от допуска до сбора процесса. Один допущенный вызов занимает один слот. |
| Запись журнала | Время, зарегистрированное имя при наличии, длительность, статус, фиксированный код | Диагностическая запись итогового исхода. Значения входа, выхода и исключений относятся к полезной нагрузке вызова. |
| Конфигурация интеграции | Платформа, версия Python и движка, ревизия и хеш GGUF, версия хоста и MCP, адреса MCP и HTTP модели, существенные флаги, хеши артефактов, итоги приёмки | Описывается в комплекте и фиксируется для прогона. Публичные имена и схемы инструментов принадлежат реестру. |

## Правила валидации

- Ядро принимает только предусмотренные версии конфигурации и манифеста.
  Разрешение путей выполняется относительно файла конфигурации либо по явно
  заданным абсолютным путям. Ошибка указывает проблемный элемент конфигурации.
- Каждый инструмент имеет непустое описание и корректную схему JSON Schema
  Draft 2020-12 с корнем `object`. Ссылки разрешаются только внутри схемы.
- Клиентские аргументы проходят проверку до запуска обработчика. Отключённый
  инструмент скрыт из каталога и недоступен при прямом вызове.
- Результат обработчика — конечный сериализуемый JSON-объект. При подаче
  результата в MCP ошибки исполнения описываются фиксированными кодами и
  сообщениями сервера.
- Лимиты размера внутреннего сообщения применяются к входу и выводу дочернего
  процесса. Проверочный профиль использует 1 МиБ на направление.

## Жизненный цикл вызова

1. Ядро получает запрос, проверяет имя, доступность и аргументы. Отказ на этом
   этапе завершается соответствующей ошибкой без запуска исполнителя.
2. Допущенный вызов получает дедлайн и запускает одного исполнителя. Успех,
   сбой или таймаут определяют ровно один итог для клиента.
3. После отправки результата сервер завершает уборку ресурсов исполнителя.
   При истечении дедлайна отправка ошибки отделена от ожидания завершения
   процесса. Опоздавший результат отбрасывается. Слот освобождается после сбора.
