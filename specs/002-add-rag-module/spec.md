# Спецификация функции — офлайн-модуль RAG для MCP-сервера

**Создано** 2026-11-22

**Статус** Черновик

**Исходная задача** Добавлять локальные документы и исходный код в базу знаний,
искать по тексту и описаниям объектов и получать исходные материалы из поиска.
Qdrant хранит поисковые векторы и описания объектов, SQLite хранит документы и
извлечённые данные.

## Clarifications

### Session 2026-11-22

- Q: Что должно происходить с документом, когда оператор хочет убрать его из базы знаний в первой версии? → A: Оператор исключает документ из поиска. Клиент с правом чтения может получить сохранённые материалы по ранее выданным идентификаторам.
- Q: Какие формулы в научных PDF должны находиться в поиске как отдельные объекты в первой версии? → A: И формулы в отдельной строке, и внутристрочные формулы индексируются как отдельные объекты.
- Q: На каком оборудовании должна пройти полная приёмка первой версии RAG? → A: Полная офлайн-приёмка первой версии проходит на CPU. GPU допускается для ускорения.
- Q: Какой объём локальной базы знаний нужно подтвердить при приёмке первой версии на CPU? → A: Контрольный корпус содержит 100 файлов и 10 000 материалов.

## Пользовательские сценарии и проверки

### Сценарий 1 — Добавить документ в базу знаний (P1)

Оператор указывает файл из настроенного каталога. После индексации он получает
статус и признак публикации. Если клиенту также разрешено чтение, полный отчёт
показывает принятую версию, число материалов по типам и участки с потерями.

**Ценность** Научную статью можно добавить целиком и искать сведения, которые
находятся в тексте, таблицах, формулах и рисунках.

**Независимая проверка** Передать через MCP по одному контрольному файлу каждого
основного формата с правами индексации и чтения и сверить полные отчёты
с размеченным содержимым файлов.

1. Из контрольных DOC и DOCX извлекаются текст, таблица, изображение и формулы.
   По идентификатору каждой формулы клиент с правом чтения получает её
   читаемое представление и место в документе.
2. Для контрольного научного PDF клиент получает структуру таблицы и области
   растрового и векторного рисунков. Внутристрочная формула и формула в отдельной
   строке доступны как разные объекты по собственным идентификаторам.
   В гибридном PDF текст с цифровой и сканированной страниц привязан
   к соответствующим номерам страниц.
3. При индексации исходников модуль выделяет функции, классы, компоненты
   и самостоятельные конструкции уровня файла. Фрагменты сохраняют
   исходные строки и отступы. Локальные изображения, таблицы и формулы
   из Markdown появляются отдельными объектами.
4. При частичном распознавании таблицы или формулы из сложного PDF
   клиент с правом чтения получает копию области страницы. Полный отчёт
   указывает объект, его место и недостающую информацию.

### Сценарий 2 — Найти сведения и открыть источник (P1)

MCP-хост передаёт вопрос на русском или английском. Модуль отбирает кандидатов
в Qdrant и переоценивает их локальной моделью реранкинга. По идентификатору
из итоговой выдачи хост запрашивает исходное содержимое и включает релевантный
контекст в запрос к модели.

**Ценность** Пользователь может проверить, откуда взяты конкретные значения,
формулы и сведения из кода.

**Независимая проверка** Подготовить контрольный корпус, задать вопросы, ответы
на которые находятся в разных типах объектов, и извлечь объекты из выдачи.

1. Запрос по значению, записанному в ячейке и отсутствующему в подписи
   и заголовках, находит таблицу. По идентификатору клиент получает строки
   и ячейки и сверяет значение с его заголовком и единицей измерения,
   если она указана.
2. Запрос по смыслу формулы или рисунка возвращает соответствующее описание.
   По идентификатору клиент получает сохранённое уравнение или изображение.
   Для объекта из PDF в выдаче указаны номер страницы и область на ней.
3. Запрос по имени или назначению метода находит нужное объявление или тело.
   Результат содержит путь, диапазон строк, исходный фрагмент и доступные
   сведения о символе, включая имя содержащего класса. По этим сведениям
   клиент различает одноимённые методы разных классов.
4. Клиент получает пустой список, если после успешного отбора нет кандидатов
   или все оценки ниже итогового порога. Поиск с пустым пулом завершается
   успешно и при отключённой модели реранкинга. При сбое поиска клиент
   получает ошибку инструмента.
5. Фильтр по типу или пути ограничивает выдачу выбранными материалами. Размер
   выдачи соблюдает заданный предел.
6. В контрольной проверке Qdrant возвращает ровно двух допустимых кандидатов.
   Обе оценки проходят порог. При лимите в один результат клиент получает
   кандидата, которого модель оценила выше. При равных оценках результатом
   становится кандидат, который был первым при векторном отборе.
7. Во время обновления индекса клиент находит актуальный фрагмент, даже если
   число более близких записей старых и незавершённых версий превышает
   максимальный размер пула.

### Сценарий 3 — Обновить индекс и восстановиться после сбоя (P1)

Оператор изменяет файл, повторяет прерванную индексацию или исключает источник
из поиска. У источника в каждый момент не более одной активной версии.

**Ценность** Повторные вызовы и перезапуски сохраняют надёжность ссылок на
источники и предсказуемость выдачи.

**Независимая проверка** Индексировать источник и обновить его. Вызвать таймаут
в двух проверках — с остановкой обработки перед публикацией и с задержкой
ответа после публикации. Отдельно обработать два разных снимка параллельно
и повторить импорт после устранения причины частичной обработки.

1. Обычный повтор полностью обработанного неизменившегося снимка возвращает
   ту же версию и идентификаторы её материалов.
2. Если обработка остановилась перед публикацией, поиск находит прежнюю версию.
   Если новая версия опубликована, но ответ не успел прийти, после таймаута
   поиск находит новую версию. Обычный повтор полной версии возвращает её
   идентификаторы без дублей.
3. Если более поздний снимок опубликован первым, завершение ранней попытки
   оставляет его активным. Идентификаторы из предыдущей выдачи по-прежнему
   доступны для чтения.
4. Обычный повтор частичной версии после устранения причины заново обрабатывает
   снимок, даже если байты исходника остались прежними. Полный результат
   публикуется по правилам FR-013. Повторный частичный результат оставляет
   ранее опубликованную версию активной.
5. Появление или исчезновение связанного изображения меняет снимок Markdown
   при тех же байтах основного файла. После появления картинки повторный
   импорт добавляет её и при полной обработке публикует новую версию.
6. При смене профиля эмбеддингов модуль выполняет запрос по готовому
   совместимому индексу или возвращает ошибку. Диагностика доступна оператору.
   Перестроение индекса из SQLite восстанавливает поиск, даже если входной
   каталог недоступен.
7. После исключения документа новые запросы пропускают все его версии.
   Клиент с правом чтения открывает прежний материал по его идентификатору.
   Обычный повтор импорта сохраняет исключение. Оператор может явно
   вернуть источник в поиск.

### Сценарий 4 — Подключить пакет на офлайн-машине (P1)

Оператор устанавливает пакет и зависимости из подготовленного комплекта,
задаёт каталог источников, подключает модуль и проверяет его обычным MCP-клиентом.

**Ценность** База знаний работает с локальными документами и моделями при
отключённом интернете.

**Независимая проверка** На чистом целевом окружении с отключённым интернетом
запустить обработчики и все модели в режиме CPU. Проиндексировать документ,
задать вопрос в MCP-хосте и зафиксировать поиск, получение объекта и передачу
результата локальной генеративной модели.

1. Подключённый модуль публикует операции индексации, поиска и получения
   сохранённого материала через действующий контракт MCP.
2. Право чтения открывает поиск и получение материалов. Право индексации
   открывает импорт и сокращённый отчёт. Полный отчёт доступен при обоих
   правах. Попытка индексации без нужного права отклоняется до чтения файла.
3. При отказе зависимости, необходимой для запроса, клиент получает ошибку
   поиска по контракту модуля v1. Оператор видит код сбойного этапа
   в локальном канале диагностики. Получение сохранённого объекта по его
   идентификатору из SQLite проходит при остановке Qdrant или моделей.

### Граничные случаи

- Если обработка прекращена из-за повреждения, шифрования, неподдерживаемого
  формата или превышения лимита, клиент получает ошибку инструмента, а оператор
  видит безопасный диагностический код. Активной остаётся прежняя версия.
- OCR применяется к каждой сканированной странице без пригодного текстового
  слоя, включая такие страницы в гибридном PDF. В полном отчёте проблемы
  распознавания указаны с номерами страниц.
- Если обнаруженная формула или таблица распознана частично, полный отчёт
  указывает недостающие данные и место объекта. По идентификатору доступно
  сохранённое представление для сверки.
- Недоступная картинка в Markdown или внешний ресурс отмечается в полном отчёте.
  Индексация Markdown использует локальные файлы из разрешённого каталога.
- При синтаксической ошибке в исходнике корректно разобранные конструкции
  сохраняют структурные метаданные. Повреждённый участок индексируется как
  текст с исходным диапазоном строк. Полный отчёт указывает диапазон и причину
  перехода к текстовому разбиению.
- Запрос неизвестного или недоступного идентификатора получает предусмотренный
  отказ. Путь за пределами каталога, включая переход по символической ссылке,
  отклоняется до чтения данных.
- При превышении лимита ответа клиент получает данные частями и может
  восстановить полное сохранённое содержимое.

## Требования

### Функциональные требования

- **FR-001. Подключение.** Самостоятельный Python-пакет подключается через
  манифест модуля v1. Стандартный MCP-клиент обнаруживает операции индексации
  файла, семантического поиска и получения материала по идентификатору.
- **FR-002. Развёртывание.** Установка, первый запуск и все операции RAG работают
  без интернета. Инструкция перечисляет версии, настройки и артефакты как минимум
  одной проверенной конфигурации. В неё входят Qdrant, средства разбора
  документов, грамматики синтаксического анализа кода, средства OCR и модели
  эмбеддингов, построения описаний и реранкинга. Доступ к инференсу ограничен
  локальной машиной по умолчанию. Офлайн-комплект также содержит артефакты
  локальной генеративной модели и MCP-хоста для сквозной проверки. Целевая
  конфигурация первой версии выполняет весь набор операций на CPU, включая
  извлечение, OCR, построение описаний, эмбеддинги, реранкинг и локальную
  генерацию в сквозном сценарии. GPU допускается для ускорения.
- **FR-003. Приём файла.** Оператор индексирует один файл по относительному пути
  внутри настроенного каталога. Модуль проверяет право индексации до чтения,
  поддерживает вложенные каталоги и применяет документированные ограничения на
  размер входных файлов и длительность обработки. Клиент получает ошибки
  по контракту v1, а оператор — локальную диагностику по FR-015.
- **FR-004. Поддерживаемые форматы.** Модуль поддерживает DOC, DOCX, PDF, TXT,
  Markdown и исходный код Python, C, C++, Qt и Kotlin. Приёмочные исходники
  включают `.py`, `.c`, `.h`, `.cpp`, `.hpp`, `.qml`, `.ui` и `.kt`.
  UTF-8 обязателен для Markdown, TXT и кода. Инструкция перечисляет остальные
  поддержанные расширения и кодировки.
- **FR-005. Word.** Из DOC и DOCX извлекаются текст, встроенные изображения,
  таблицы и формулы. Для встроенного изображения сохраняется исходное
  представление, если его удалось извлечь. Для таблиц сохраняются порядок
  строк и столбцов, значения и объединения ячеек. Поддерживаются встроенные
  объекты Microsoft Equation Editor и MathType в обоих форматах и нативные
  формулы Word в DOCX. Каждая извлечённая формула получает идентификатор и место
  в документе. По идентификатору доступна структурированная запись или
  читаемое изображение. Доступная нативная запись или исходный встроенный
  объект также сохраняются. Если в DOC формула представлена изображением,
  модуль сохраняет его при распознавании объекта и указывает в полном
  отчёте, что нативная запись отсутствует. Обнаруженные формулы без читаемого
  представления перечисляются в полном отчёте с указанием местоположения.
  [Редакторы формул Word](https://support.microsoft.com/en-us/word/editing-equations-created-using-microsoft-equation-editor) ·
  [Формулы при сохранении в старом формате Word](https://support.microsoft.com/en-us/word/compatibility-changes-between-versions) ·
  [Встроенные объекты MathType](https://docs.wiris.com/en_US/mathtype-support-notices-category/cant-group-mathtype-equations-with-microsoft-word-drawings)
- **FR-006. PDF.** Из научной статьи извлекаются текст, таблицы, формулы и
  рисунки, включая векторные схемы. OCR выполняется локально для отдельных
  сканированных страниц без пригодного текстового слоя, включая страницы
  смешанных документов. Модуль сохраняет извлечённый оригинал объекта,
  если он доступен, иначе сохраняет изображение области страницы. При
  распознавании таблицы сохраняются порядок строк и столбцов, значения
  и объединения ячеек. Внутристрочные формулы и формулы в отдельной строке
  индексируются как отдельные объекты. Для каждой формулы сохраняются
  собственный идентификатор, номер страницы и координаты области. При успешном
  распознавании сохраняется символьная запись с математической структурой.
  При неполном распознавании таблицы или
  формулы сохраняется изображение области, а полный отчёт указывает
  недостающие данные. Для фрагментов и объектов сохраняется номер страницы.
  Для объектов сохраняются также координаты области в объявленной системе
  отсчёта.
- **FR-007. Текст и Markdown.** Текст разделяется на фрагменты с координатами
  в источнике. Из Markdown дополнительно извлекаются таблицы GFM, формулы LaTeX
  и изображения по допустимым локальным относительным ссылкам. Снимок Markdown
  включает байты исходника и для каждого такого изображения — его байты либо
  отметку об отсутствии. Появление, исчезновение или изменение изображения
  требует повторной обработки. Если изображение отсутствует, полный отчёт
  указывает пропуск.
- **FR-008. Описания.** Каждое доступное в поиске изображение, таблица и формула
  получает текстовое описание на основе собственного содержимого. Для рисунка
  описание передаёт различимые элементы и их связи, для таблицы — смысл
  столбцов, единицы и содержимое, для формулы — читаемую запись и назначение,
  если оно следует из уравнения или контекста. Фактические утверждения
  соответствуют доступному представлению объекта. Неоднозначные значения,
  единицы и символы помечаются. Если содержательное описание получить
  не удалось, полный отчёт указывает тип и место объекта и идентификатор
  сохранённого представления при его наличии.
- **FR-009. SQLite.** SQLite является источником данных. В ней доступны
  неизменённые байты принятой версии документа, извлечённые фрагменты, исходные
  или визуальные представления объектов, их описания, типы, идентификаторы и
  координаты. Для фрагментов кода сохраняются метаданные синтаксической
  конструкции. Идентификатор объекта связан с конкретной версией источника.
  Для активных версий SQLite также хранит данные снимков и поисковые
  представления, необходимые для восстановления векторного индекса.
- **FR-010. Qdrant.** Qdrant хранит векторы текстовых фрагментов и описаний
  изображений, таблиц и формул, тексты этих описаний и метаданные для поиска.
  Поисковое представление таблицы включает её описание, распознанные значения
  ячеек, соответствующие заголовки строк и столбцов и указанные в источнике
  единицы измерения. Длинная таблица может иметь несколько поисковых записей
  с общим идентификатором таблицы и координатами охваченных ячеек.
  У каждой поисковой записи есть идентификатор соответствующего материала
  в SQLite. Оригиналы файлов и извлечённых изображений, таблиц и формул
  извлекаются из SQLite. Поисковый запрос использует один готовый индекс
  с совместимым профилем эмбеддингов для документов и запроса. При отсутствии
  совместимого индекса поиск возвращает ошибку по контракту v1, а оператор
  получает код несовместимости. Оператор может перестроить индекс из SQLite
  при недоступном входном каталоге. Поиск переключается на новый профиль после
  готовности его индекса.
- **FR-011. Поиск.** Клиент может задать текст запроса на русском или английском,
  ограничить число результатов и отфильтровать поиск по типу материала или
  файлу. Выдача упорядочена по оценке модели реранкинга согласно FR-017.
  Каждый результат содержит текст либо описание, итоговую оценку релевантности,
  тип, идентификаторы материала, источника и его версии, относительный путь
  и координаты. Оператор задаёт порог по умолчанию. Клиент может указать
  допустимый порог в конкретном запросе. Для выбранной модели документируются
  шкала итоговой оценки, допустимые значения порога и предел размера выдачи.
  Проходной считается конечная оценка, равная порогу или превышающая его.
  Пустая выдача и ошибка имеют разные исходы MCP-вызова. В режиме CPU поиск
  поддерживает не менее 100 файлов с активными версиями и 10 000 доступных
  поиску материалов. Материалы считаются по уникальным идентификаторам
  фрагментов и объектов.
- **FR-012. Получение материала.** По идентификатору из выдачи или полного
  отчёта клиент с правом чтения получает сохранённый фрагмент или объект,
  его метаданные, описание при наличии и список доступных представлений.
  Исходный файл доступен по идентификатору версии. Операция поддерживает
  чтение крупных данных частями с сохранением их типа и точности. Чтение
  из SQLite работает после изменения или удаления входного файла, при
  остановке Qdrant и при недоступности моделей. Идентификаторы опубликованных
  версий позволяют читать материалы этих версий и после обновления индекса.
- **FR-013. Повторные вызовы и согласованность.** Снимок фиксирует байты
  источника и состояние учитываемых локальных ресурсов. При обычном повторе
  того же снимка модуль переиспользует полную активную версию и идентификаторы
  её материалов, если версия доступна в совместимом индексе. Частичная
  активная версия при обычном повторе обрабатывается заново. Оператор может
  явно запросить повторную обработку полной версии. Версия становится
  активной целиком после сохранения материалов в SQLite и готовности
  поисковых записей для каждого индексируемого материала. Если обработка
  остановилась до публикации, поиск продолжает использовать прежнюю версию.
  Если публикация состоялась, новая версия остаётся активной, даже когда
  клиент получил таймаут из-за задержки ответа. Обычный повтор возвращает
  уже опубликованную полную версию без дублей. При параллельных вызовах
  учитывается порядок фиксации снимков. Более ранний снимок уступает уже
  опубликованному позднему. После перезапуска сохраняются выбранная
  активная версия и ссылки на ранее опубликованные материалы. Оператор
  с правом индексации может исключить источник из поиска. После исключения
  у источника нет активной версии, а сохранённые материалы доступны
  по прежним идентификаторам с правом чтения. Состояние сохраняется после
  перезапуска и обычного импорта. Вернуть источник в поиск можно явным
  запросом оператора на публикацию. Попытка индексации, начатая до
  исключения источника, сохраняет его исключённым.
- **FR-014. Статус индексации.** Успешный вызов возвращает статус и признак
  публикации этой попыткой. Статус различает полную обработку,
  переиспользование версии, частичную обработку и завершение обработки
  снимка, уступившего более поздней активной версии, и состояние
  исключённого источника при обычном импорте. Первый частичный импорт
  публикуется при готовности хотя бы одного материала к поиску.
  При частичной обработке без готовых к поиску материалов полный отчёт
  содержит идентификаторы доступных представлений для сверки.
  Частичное обновление оставляет активной ранее опубликованную версию.
  Полный результат публикуется по правилам FR-013. Если перед
  публикацией отказала обязательная для индексации зависимость или
  обработка завершилась без извлечённых материалов, вызов возвращает
  ошибку по контракту v1. При наличии прав индексации и чтения полный
  отчёт дополнительно содержит идентификаторы источника, обработанной и
  активной версий при наличии, число материалов по типам и сведения
  о пропусках с местоположением и идентификаторами сохранённых
  представлений. При одном праве индексации доступны статус и признак
  публикации.
- **FR-015. Полномочия и конфиденциальность.** Права на индексацию и чтение
  назначаются отдельно в конфигурации экземпляра. Право чтения проверяется
  для поиска, исходников, объектов и метаданных, включая поля полного
  отчёта индексации. Содержимое источников, макросы и исходный код
  обрабатываются как данные. Для ошибок выполнения MCP-клиент получает
  `isError: true` и сообщение, предусмотренное контрактом v1.
  Для сбоев, обнаруженных модулем, оператор получает фиксированные коды
  причины и этапа в отдельном локальном канале диагностики. Этапы включают
  разбор, работу с хранилищами, эмбеддинги и реранкинг. Канал содержит
  только служебные метаданные, например время, этап и код. Содержимое
  корпуса и запросов остаётся на машине экземпляра.
- **FR-016. Структурная индексация кода.** Модуль разбирает исходный код
  с помощью Tree-sitter или другого инструмента, предоставляющего синтаксическое
  дерево и координаты конструкций. Фрагменты формируются по границам функций,
  методов, классов, пространств имён и других конструкций, применимых к языку
  файла. Индексируется и самостоятельный код уровня файла, включая
  определения макросов, объявления констант и выражения инициализации.
  Для Qt учитываются конструкции C++, в том числе объявления сигналов
  и слотов, а также иерархия QML-компонентов и виджетов из файлов `.ui`.
  При разбиении большой конструкции её части сохраняют ссылку на общий символ,
  доступную сигнатуру и собственный диапазон строк. Для каждого фрагмента
  модуль сохраняет исходный текст и возвращает в выдаче язык, тип конструкции
  и доступные имя, область видимости и сигнатуру. При формировании представления
  для поиска учитываются эти сведения, импорты или включения на уровне файла
  и связанные комментарии, если они доступны. Текстовое разбиение применяется
  к участкам, для которых синтаксическое дерево не даёт надёжных границ.
  Такой участок явно помечается и остаётся доступным для поиска по тексту.
  [Документация Tree-sitter](https://tree-sitter.github.io/tree-sitter/)
- **FR-017. Реранкинг.** Для каждого запроса модуль использует один
  согласованный срез опубликованных версий от векторного отбора в Qdrant
  до формирования выдачи. Активность версии, полномочия и фильтры запроса
  учитываются до применения лимита пула. Оператор задаёт размер пула,
  превышающий максимально допустимое число результатов в выдаче.
  Локальная модель оценивает содержимое каждого кандидата вместе с запросом.
  Для кода она получает доступный контекст символа, для изображения или
  формулы — описание, для таблицы — поисковое представление по FR-010.
  После реранкинга результаты сортируются по убыванию оценки. При равенстве
  сохраняется порядок векторного отбора. Порог и лимит выдачи применяются
  к результатам реранкинга. Реранкер требуется для поиска с непустым пулом.
  Пустой пул после успешного отбора даёт пустую выдачу. Недоступность
  реранкера, неконечная оценка или сбой при обработке непустого пула
  дают ошибку поиска.
  [Схема двухэтапного поиска в документации Sentence Transformers](https://www.sbert.net/examples/sentence_transformer/applications/retrieve_rerank/README.html)

### Ключевые сущности

- **Источник** — документ или исходник по относительному пути. У источника
  может быть несколько сохранённых версий и не более одной активной.
  Для исключённого источника активной версии нет.
- **Версия источника** — принятые байты файла, идентификатор версии, статус
  обработки и связанные фрагменты и объекты.
- **Снимок** — зафиксированное состояние исходника и учитываемых локальных
  ресурсов, по которому выполняется попытка индексации.
- **Фрагмент** — отрывок текста или кода с идентификатором и координатами
  в конкретной версии источника. Фрагмент кода содержит доступные сведения
  о синтаксической конструкции и её положении в файле.
- **Извлечённый объект** — изображение, таблица или формула с идентификатором,
  местом в источнике, описанием и доступными представлениями.
- **Поисковая запись** — вектор и поисковые метаданные фрагмента или объекта.
  Идентификатор связывает результат с конкретным сохранённым материалом.

## Критерии успеха

### Измеримые результаты

- **SC-001. Покрытие форматов.** Контрольный корпус покрывает DOC, DOCX,
  научный PDF с текстовым слоем, скан PDF, гибридный PDF, PDF со сложным
  объектом, TXT, Markdown, Python, C, C++, Qt C++, QML, Qt Designer `.ui`
  и Kotlin. Для DOC проверяются формулы Microsoft Equation Editor, MathType
  и формула, сохранённая как изображение. Для DOCX проверяются нативная
  формула Word и встроенные объекты Microsoft Equation Editor и MathType.
  В PDF размечены таблица с объединениями ячеек, формулы внутри строки
  и в отдельной строке, растровый и векторный рисунки. Каждый контрольный
  файл даёт поисковые материалы.
- **SC-002. Проверяемость материалов.** Для каждого размеченного объекта
  с доступным представлением клиент получает тип, местоположение и отдельный
  идентификатор. Уравнения Word и MathType доступны в читаемом виде.
  В читаемом PDF значения, порядок и объединения ячеек совпадают с эталоном.
  Поиск с фильтром по формулам возвращает внутристрочную формулу и формулу
  в отдельной строке как разные объекты. У обеих верны номер страницы,
  координаты области, эталонные символы и математическая структура записи.
  В сложном PDF частично распознанный объект
  доступен в виде изображения области, а полный отчёт указывает,
  какие данные утрачены при извлечении. В гибридном PDF контрольная фраза
  со сканированной страницы присутствует в извлечённом тексте и находится
  поиском с правильным номером страницы. Для каждого размеченного объекта
  в поиске описание содержит заданный эталоном факт. Утверждения о значениях,
  единицах и обозначениях, помеченные как достоверные, совпадают с источником.
  Если обнаруженный объект пропущен или описание получить не удалось,
  полный отчёт указывает тип, место и недостающий результат.
- **SC-003. Релевантность.** До приёмки фиксируются шесть запросов на русском
  и шесть на английском с целевыми материалами, размеченными по источнику
  и месту в нём. После реранкинга один из целевых материалов входит
  в первые пять результатов не менее чем для пяти запросов на каждом языке.
  Среди зачтённых запросов есть как минимум по одному для текста, кода,
  таблицы, формулы и рисунка. В табличном запросе значение берётся из ячейки
  и отсутствует в подписи и заголовках.
- **SC-004. Целостность.** При таймауте с остановкой обработки до публикации
  поиск находит прежнюю версию. При таймауте после публикации поиск и обычный
  повтор находят опубликованную полную версию. При параллельной обработке
  двух разных снимков поздний снимок, опубликованный первым, остаётся
  активным. Перезапуск сохраняет одну активную версию, а чтение по прежним
  идентификаторам возвращает материалы прежней версии. Параллельные обычные
  повторы полного снимка возвращают одну версию с теми же идентификаторами.
  Первый частичный импорт
  с готовым материалом публикуется. Повторная частичная попытка сохраняет
  прежнюю активную версию, а повтор после устранения причины публикует
  полный результат. Отдельно проверяются появление и исчезновение
  изображения без изменения байтов Markdown. После отказа Qdrant до
  публикации поиск находит прежнюю версию, когда сервис снова доступен.
  При перестроении индекса из SQLite с недоступным входным каталогом
  запрос либо использует один готовый совместимый профиль, либо возвращает
  ошибку. После перестроения поиск по новому профилю проходит. Данные
  крупного объекта, полученные частями, побайтно совпадают с сохранённым
  представлением. После исключения источника поиск пропускает его материалы
  даже после перезапуска и обычного импорта, а ранее выданный идентификатор
  даёт доступ к тому же материалу. Проверяются отказ в исключении при праве
  только на чтение и возврат источника после явной публикации оператором.
- **SC-005. Офлайн-приёмка.** Полная приёмка проходит в чистом окружении
  с отключённым интернетом, в режиме CPU без доступа к GPU. В отчёте
  фиксируются процессор, объём оперативной памяти и версии используемых
  компонентов и моделей. Оператор по инструкции устанавливает пакет,
  обнаруживает базовые операции,
  индексирует контрольный документ и задаёт вопрос в MCP-хосте. В трассе
  проверки видны MCP-вызов поиска с реранкингом, получение объекта по
  идентификатору и передача фактических результатов вызовов в следующий запрос
  к локальной генеративной модели. Ответ модели содержит контрольное значение
  из документа, отсутствующее в вопросе. Поиск и получение объекта
  укладываются в задокументированный дедлайн на зафиксированном окружении.
  При нагрузочной проверке на CPU корпус содержит не менее 100 файлов
  с активными версиями и 10 000 доступных поиску материалов по уникальным
  идентификаторам. На этом корпусе выполняются запросы из SC-003. Для каждого
  фиксируется длительность поиска с реранкингом и проверяются дедлайн
  и попадание целевого материала в выдачу по SC-003.
- **SC-006. Доступ и отказы.** Для четырёх сочетаний прав проверяются доступ
  к трём операциям и состав отчёта по FR-014 и FR-015. Путь за пределами
  каталога отклоняется до чтения. При отключении по очереди Qdrant, модели
  эмбеддингов и модели реранкинга запрос, которому нужна эта зависимость,
  возвращает MCP-ошибку. Оператор получает код сбойного этапа. Проверяются
  журнал ядра и отдельный канал диагностики модуля. Контрольные значения из
  аргументов, результатов и текстов исключений отсутствуют в обоих.
  При каждом отказе сохранённый объект доступен по идентификатору,
  а стандартный клиент успешно вызывает другой модуль сервера. При
  остановленном реранкере и доступных остальных зависимостях индексация
  работает.
- **SC-007. Структура кода.** В размеченных примерах Python, C, C++, Qt C++,
  QML, Qt Designer `.ui` и Kotlin извлекаются ожидаемые конструкции и
  диапазоны строк. Два одноимённых метода в разных классах различаются
  в выдаче по содержащему классу. Части большой функции содержат сведения
  об одном символе. При синтаксической ошибке в отдельном участке этот участок
  доступен с пометкой текстового разбиения, а соседняя корректно разобранная
  функция остаётся доступной со структурными метаданными. Запросы по именам
  контрольного макроса и константы, а также по назначению выражения
  инициализации на уровне файла возвращают соответствующие фрагменты
  с правильными диапазонами строк.
- **SC-008. Реранкинг.** В офлайн-проверке с выбранной моделью фиксируются
  запрос, лимит K, набор кандидатов, исходные позиции и итоговые оценки.
  Размеченный кандидат с исходной позицией ниже K входит в итоговые первые K.
  На двух кандидатах с лимитом в один результат проверяются перестановка
  и порядок при равных оценках. Проверки порога покрывают настройку оператора,
  переопределение клиентом, включение результата с оценкой на границе
  и пустую выдачу при всех оценках ниже порога. При отключённой модели
  пустой пул даёт пустую выдачу, а непустой — ошибку. При обновлении индекса
  проверяется поиск актуального фрагмента, когда более близкие записи
  старых и незавершённых версий могли бы заполнить весь пул.

## Допущения и границы

- Первая поставка обслуживает один локальный корпус на настроенный экземпляр.
  Оператор заранее помещает файлы в доверенный каталог. Импорт запускается
  для отдельного файла или его обновления по вызову MCP.
- Версии обновлённых и исключённых из поиска источников сохраняются в SQLite
  для проверки ранее выданных ссылок. Объём хранилища учитывает историю индексации.
- MCP-хост управляет диалогом и генерацией ответа. Операции модуля предоставляют
  контекст, ссылки на источники и сохранённые материалы.
- На приёмке используются читаемые Word-документы и PDF-статьи на русском и
  английском, включая проверяемый скан. Сложная вёрстка, низкое качество
  изображения и формулы с нестандартными шрифтами могут дать частичный
  результат. Для таких исходников критерий — явный отчёт о выявленных потерях
  и возможность сверки с доступным представлением.
- Для первой поставки контекст кода ограничен сведениями, извлекаемыми
  из отдельного файла. Разбор работает офлайн на исходных файлах.
- Имена операций, схемы MCP, способ локального инференса и выбор моделей,
  выбор грамматик и правила для неоднозначных расширений (например, `.h`),
  размер пула кандидатов, точные лимиты и организация переиндексации
  уточняются в техническом плане.
