# План реализации — офлайн-модуль RAG для MCP-сервера

**Ветка** `main` · **Фича** `002-add-rag-module` · **Дата** 2026-11-22

**Основание** [Спецификация](spec.md)

## Краткое описание

Добавить самостоятельный Python-пакет с манифестом MCP v1. Он индексирует
локальные документы, хранит представления и историю в SQLite, ищет по
активным версиям в Qdrant и переоценивает кандидатов локальным реранкером.
Чтение по идентификатору работает из SQLite при остановке моделей или Qdrant.
Исключение источника, восстановление индекса и его обслуживание доступны
оператору через локальную CLI.

Полный сценарий выпуска проверяется на CPU. Debian 13 amd64 с CUDA 13.2
используется как профиль ускорения llama.cpp. Имена инструментов, профиль
хранения и правила публикации общие для обоих профилей.
[Решения по платформе](research.md#r1-debian-13-cpu-и-cuda-132)

## Технический контекст

| Область | Решение |
|---|---|
| Язык и платформа | CPython 3.13, Debian 13 amd64. CPU для полной приёмки. CUDA Toolkit 13.2.x для ускорения, с проверкой драйвера и compute capability. |
| Интеграция | `mcp-offline-core` 0.1.0, MCP v1, Streamable HTTP на loopback. Синхронный обработчик в выделенном ядром процессе. `mcp-rag-check launch` запускает локальные роли `llama-server b12359` и привязывает готовность эмбеддера к эффективному профилю и экземпляру процесса. |
| Извлечение | PDFium, Docling Standard с TableFormer, Tesseract rus+eng, PP-DocLayoutV2 и PP-FormulaNet_plus-S. Для Word — `defusedxml`, `olefile` и LibreOffice через UNO в Bubblewrap. Для Markdown — markdown-it. Для кода — Tree-sitter с пакетами грамматик и XML-разбором Qt Designer. |
| Данные | APSW 3.54.1.0 и SQLite в режиме WAL на локальном диске. Qdrant v1.20.2 REST с точным cosine-поиском по 1024-компонентным эмбеддингам. |
| Модели | Qwen3 Embedding 0.6B, Qwen3 Reranker 0.6B, Qwen3-VL 2B и Qwen3 4B для хоста. Артефакты и настройки фиксируются в ведомости. |
| Проверки | pytest для обработчиков, барьеры сбоя с реальными Qdrant и SQLite, MCP SDK для контрактных тестов, офлайн-стенды с проверенными процессами CPU и CUDA. |
| Масштаб | Один корпус и один сервер Qdrant на машине. Приёмка на ≥100 активных файлах и ≥10 000 уникальных поисковых материалах. Пул 32, выдача до 20. |
| Контрольный стенд | Проектная конфигурация — 8 физических ядер x86-64 с AVX2, 32 ГиБ RAM и SSD. Замеры фиксируют фактический CPU, память, модели, число потоков и размер корпуса. |
| Бюджеты | CPU: поиск ≤45 с, одна часть чтения ≤3 с, индексация ≤900 с. Выделенный экземпляр ядра использует общий дедлайн 960 с и 2 слота. Эти бюджеты проверяются на стенде. |
| Границы | Вход ≤64 МиБ, до 100 страниц PDF и до 256 МиБ распакованных частей DOCX. Рамки подлежат проверке на целевом корпусе и документируются оператору. Сообщение обработчика укладывается в лимит ядра 1 МиБ. |

| II. Контракт модулей | Проверка пройдена. Модуль оформляется отдельным пакетом. | Импорт, поиск и чтение имеют собственные схемы и обработчики. Ядро, контекст и транспорт сохраняют существующий публичный контракт. |
| III. Совместимость бэкендов | Проверка пройдена. У каждого выбранного адаптера будет закреплённый профиль. | Для b12359 заданы модели, эффективные параметры и контрольные векторы. CUDA-приёмка подтверждает ускорение у каждого процесса, который обслуживает проверяемый endpoint. |
| IV. Валидация и конфиденциальность | Проверка пройдена. Доверенные полномочия, извлечение локальных данных. | Границы файлов проверяются при открытии. LibreOffice работает с ограниченным доступом к снимку и локальному окружению. Полные отчёты и метаданные требуют права чтения. Логи содержат служебные коды. |
| V. Совместимость и ошибки | Проверка пройдена. Существующий контракт ошибок и дедлайнов применяется к новому модулю. | Клиент получает `isError` от ядра. Прерванная до публикации обработка сохраняет прежнюю версию. Потеря ответа после коммита допускает идемпотентный повтор. |
| VI. Автономность | Проверка пройдена. Пакеты, бинарники, веса и грамматики переносятся на Debian. | Сценарий установки с отключённой сетью и приёмка CPU определены. Драйвер и CUDA относятся к отдельной поставке ускорения. |

Пакет использует подход существующих инструментов ZIP и PDF. Точка входа
оператора `mcp-rag-admin`, проверочный запуск `mcp-rag-check`, и рабочий
манифест распространяются с wheel и комплектом офлайн-установки.
Сборка повторно использует ведомости и проверку SHA-256 существующего
офлайн-комплекта. Публичная форма задана [контрактом](contracts/rag-tools.md).

## Порядок реализации

1. Проверить рискованные зависимости на Debian CPU. Запустить закреплённые
   GGUF и проверить реранкер и эмбеддинги на эталонах. Для DOC проверить
   оригинальные потоки MathType и формулу, сохранённую только рисунком.
   Для PDF проверить повёрнутую обрезанную страницу, сканированную таблицу,
   отдельные идентификаторы формул обоих типов и локаторы только с `page`.
   Зафиксировать версии и результаты до подключения парсеров к MCP.
2. Реализовать модель SQLite, хранилище Qdrant и публикацию через подготовленные
   точки и атомарный указатель. Проверить сбои до и после коммита, параллельные
   импорты, исключение и перестроение индекса из SQLite. Для импорта и
   перестроения остановить исполнителя на барьере после последнего
   подтверждения Qdrant и до коммита. Проверить, что очистка ждёт коммита
   или отката и сохраняет точки опубликованной версии.
   [Модель данных](data-model.md)
3. Реализовать обработчики и локальную CLI. Отвязать хранилище от вызовов
   модели в чтении. В индексировании выполнять стадии по собственному
   монотонному дедлайну. Завершать подпроцессы конвертации и освобождать
   временные файлы при остановке исполнителя. Ограничить время инференса
   на локальном адаптере. Проверить прямое чтение представлений из полного
   отчёта, чтение длинных метаданных частями и общий `symbol_id` у частей
   одной декларации. Проверить сброс аттестации после замены процесса и
   переход на проверенный профиль с другим `pooling` через `rebuild`.
4. Проверить все заявленные форматы и SC-001–SC-008. Собрать и проверить
   комплект на чистом офлайн-стенде. Для CUDA 13.2 подтвердить связь
   проверяемых портов с процессами, использующими GPU, и offload проектора.
   Повторить проверки интерфейсов и релевантности на тех же контрольных
   материалах.
